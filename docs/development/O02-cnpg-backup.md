# O02 CNPGバックアップ

> **更新日** 2026-09-12 ・ **区分** 開発計画 ・ **読む人** 開発者

**区分**: 既存DB提供のバックアップ追加 ・ **状態**: CNPGとDB APIは実装済み、バックアップは未整備。

## 目的・現状・配備先

既存Kubernetesで提供する利用者DBを、整合したバックアップから復元できるようにする。[Kubernetes運用](../operations/kubernetes.md)はGarageへのCNPGバックアップを残作業に挙げている。`platform/flux/apps/cnpg/`にOperator、`cloud/api/internal/cnpg/`にCluster作成処理がある。ポケモンDBは[A01](A01-pokemon-ai.md)のgame1内Composeが所有し、本計画へ移さない。

## 変更範囲と実装

1. 稼働Operator・PostgreSQL版と対応するバックアップ機構を確認し、対象版が支持するS3連携方式を固定する。検証用DBでGarageへのベースバックアップ・WAL保存・復元を組み合わせる。
2. Operator・共通設定・SecretはFlux、動的Clusterとそのバックアップ設定はクラウド側所有に揃える。動的ClusterをFluxへ二重宣言しない。既存DBへの適用も新規DBと同じ状態へ収束するよう設計する。
3. DB単位の保存prefix・資格情報・保持・失敗表示を分離する。削除APIでバックアップまで即時削除しない運用を明記し、孤立世代の扱いを管理者の復旧手順へ記す。
4. Garageは同一ホスト内の保存先なので、ホスト障害をカバーする既存外部先へのコピーも[O03](O03-restore.md)と組み合わせる。外部先が未確定なら復旧範囲を明記し、ホスト喪失対応完了とはしない。
5. 別名Clusterへ復元し、データ・ロール・権限と時点復旧を確認してから接続を切り替える。今回の計画作成ではAPIやClusterスキーマの変更を行わない。

## 依存と並列作業

- **開発開始:** 設定案・モック・所有境界の整理は独立着手できる。
- **実機検証:** CNPG・Garageの稼働、対象版の対応確認、S3資格情報、[I01](I01-resources.md)の復元用余力が必要。外部保存のみO03と保存先確認を共有する。
- **競合:** CNPG共通設定・APIのCluster作成処理・DB namespace権限は担当を一本化する。復元用DBと本番DBを識別し、大量WAL転送を[O01](O01-cloud-backup.md)のバックアップと調整する。

## 検証・完了条件

新規・既存DBの定期バックアップ、書込継続中のWAL保存、資格情報失効と転送失敗、別Clusterへの復元を確認する。指定した時点の検証データが戻り、他DBのデータ・権限へ影響しない。バックアップの最新性と復元日を記録し、Garage喪失を含む保証範囲を明示する。
