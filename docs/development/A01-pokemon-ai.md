## 実装手順

1. 外部リポジトリの取得元・版、実稼働イメージ、ダンプ・設定の受渡し方法を確認する。未取得の間は想定構成の整理とダミーデータで移行手順を作る。実データやSecretをGitへ含めない。
2. `pokemon_rdb` と `openwebui`、`openwebui.rag.pokedex_documents`、pgvector・ロール・権限、WebUI状態・`WEBUI_SECRET_KEY`、agent設定・migration/provisionを移行一覧にする。実稼働のEmbeddingモデル・次元を保ち、版更新と再Embeddingを同時に行わない。
3. game1のOS・コンテナ基盤に合うComposeを整備し、ポケモン専用のDB資格情報と保存先を使う。`pokemon_reader` / `rag_reader` の読み取り制限とWebUIの利用者認証を維持し、既存SSOがあればidentity統合時のアカウント対応を確認する。
4. 更新・取り込みを止め、両DBとWebUI状態の整合バックアップを隔離先に復元する。外部コード取得後に `fingerprint_data.py` の実体・使い方を確認し、件数・指紋と検索結果を比較して入口を切り替える。旧データは合格後も切戻し用に保持する。

## 依存と並列作業

- 開発開始: ダミーデータ・構成整理はなし。実コード改修と本移行には外部コード・データ・管理者提供の設定が必要。
- 配備・切替: [I01](I01-resources.md)のRAM・DB/索引/WAL/復元容量確認、[N05](N05-https.md)のWeb入口。ローカル推論の結合確認のみ[A02](A02-ollama.md)に依存し、SQL/既存推論先の検証は並行する。
- 競合調整: game1の再起動・GPUはG/A担当と調整する。A03とはDB・ロール・文書権限を分離し、利用者向けDB削除APIの対象にしない。

## 検証・完了条件

- 両DBの表件数・指紋と拡張・ロールが一致し、読み取りロールで書き込み・他用途DBへのアクセスが拒否される。
- SQL検索、図鑑検索、WebUIのチャット・SSE、推論停止時のエラーを確認する。VM停止中は検索もBotも止まる旨を運用へ反映する。
- 隔離復元と再配備・VM再起動でDB/鍵/チャットが保持され、切替後の書き込み差分を保全する切戻しを文書化する。
