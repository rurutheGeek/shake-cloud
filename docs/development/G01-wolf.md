# G01 Wolfの構成管理と実機確認

> **更新日** 2026-09-12 ・ **区分** 開発計画 ・ **読む人** 開発者

これは開発計画であり配備完了の記録ではありません。[配置・所有境界・並列作業の共通ルール](index.md)を参照してください。番号は実施順を表しません。

## 目的・現状

**状態**: 新規構成管理・既存VMの実機確認

[配備台帳](../operations/handover.md)ではgame1がBazzite・GPUパススルーで稼働している。[ゲーム設計](../architecture/gaming.md)はWolfの二人利用を設計しているが、リポジトリにWolf配備定義はなく、動作合格も確認できない。

配備先・開発範囲: **既存game1。開発先 `stacks/game/`。VMの所有者はクラウドAPIであり、新stateで再作成しない**。

## 実装手順

1. 既存の手動配備・プロフィール・ペアリング・コンテナ・GPUデバイスを読み取りで棚卸しする。Bazziteの更新/コンテナ方式を確認し、Debian/Ubuntu専用Playbookをそのまま適用しない。
2. 導入時の公式仕様に合わせてWolfの版・権限・GPU/入力デバイスを固定し、再配備できる設定を作る。二人のプロフィールと永続データを分け、動的なペアリング情報を固定設定で上書きしない。
3. 一人接続でGPU描画・ハードウェアエンコード・音声・入力を確認し、二人の独立セッションへ広げる。必要性を確認するまで追加の仮想画面構成を増やさない。
4. GPUの停止再開、プロフィール保全、ペアリング解除/復旧、バックアップを手順化し、G02へセッション起動方法を渡す。

## 依存と並列作業

- 開発開始: なし。サンプル設定の構成管理と利用者データの配置設計から開始する。
- 配備・切替: [I01](I01-resources.md)と既存game1の利用者調整、GPU/OSの棚卸し。Azahar自体の完成はWolf単体検証の前提にしない。
- 競合調整: G02と `stacks/game/` の共有設定・プロフィールの編集範囲を分ける。A02とドライバー・GPU・VM再起動の時間を調整する。

## 検証・完了条件

- 二人の画面・音声・入力が混線せず、それぞれ接続・切断・再接続できる。無許可のクライアントをペアリングしない。
- GPU描画/エンコードの実利用を確認し、VM停止再開後にホスト再起動なしで再利用できるか結果を記録する。
- プロフィールとペアリング状態を復元し、再配備・VM再起動でも保持される。ゲーム固有の性能はG02/G03で別に判定する。
