# I07 クラウドポータルのUI改善

> **更新日** 2026-10-03 ・ **区分** 開発計画 ・ **読む人** 開発者

**区分**: 既存機構の改善 ・ **状態**: **ファビコン、タグの表示・絞り込み・作成時の指定、作成後の名前・タグの変更、メニューと画面の整理、インスタンス一覧の再構成と詳細画面を実装（2026-10-03）。** 配備はまだしていない（下の「インスタンス画面の作り直し」を参照）。

## 目的・現状・配備先

クラウドVMが増える（[配置と命名の再編](../architecture/placement-naming.md)で、アプリと開発VMをクラウドVMへ寄せる）ので、ポータルを見分けやすく・探しやすくする。配備先は cloud-01 のクラウドAPI（`cloud/api/internal/server/web/`。Goのバイナリへ埋め込み）。

現状（2026-10-03）:

- **ファビコンが無い。** ブラウザーのタブで、ポータル・VMのコンソール・ヘルプが見分けられない。
- メニューが14項目、横1列に並んでいる（概要・ヘルプ・インスタンス・ボリューム・セキュリティグループ・S3・データベース・関数・イメージ・ISO・SSH鍵・アクセスキー・操作履歴・管理設定）。
- インスタンス一覧は9列（名前・所有者・状態・IP・イメージ・構成・ディスク・セキュリティグループ・操作）で、用途（サービス／開発）で分かれていない。
- 配色は明・暗の両方に対応済み（`portal.css` の変数）。外部のライブラリは使っていない。

## 変更範囲と実装

1. **ファビコン（実装済み）。** 図柄は**空飛ぶ鮭**（shake＝鮭、cloud＝空）を**マテリアルデザイン**（平らな面・単純な形・影やグラデーション無し）で描く。水色の角丸の地に、白い翼のあるサーモン色の鮭。`/static/favicon.svg` として埋め込み、`index.html`・`console.html`・`help.html`・`message.html` の4枚すべてから参照する。地の色を持つので、明・暗どちらのタブでも同じ絵で見える。`/favicon.ico` は用意していない（開発機に画像変換の手段が無い。SVG のファビコンを読めない古いブラウザーではアイコンが出ない）。
2. **タブの題名（対応不要）。** コンソールの題名は既に「コンソール — <VM名>」になっていた（計画時の見落とし）。
3. **メニューと画面の整理（実装済み・2026-10-03）。** メニューを「計算」「データ」「アカウント」の3つに分け、広い画面では左の列に、狭い画面では上に並べる。**1画面に1セクションだけを表示する**（以前は14セクションが1本の長いページに並んでいた）。開いている項目はメニューで強調する。URL（`#instances-view` など）は変えていないので、リンク・戻るボタン・再読み込みはそのまま使える。スクリプトが動かないときは全セクションが見える。表記も揃えた（`admins` → 管理者、「上限」→「管理設定（上限）」、「S3ストレージ」→「S3バケット」）。ヘッダーにロゴ。
4. **タグの表示・絞り込み・作成時の指定（実装済み）。** 用途のための専用の列は作らない。インスタンス一覧の名前の下に `Name` 以外のタグを並べ、タグを押すとそのタグで絞り込む（検索欄がタグも探す）。作成フォームに「タグ（任意）」の欄を足し、`Purpose=dev, Team=home` の形で付けられる。用途はこのタグで表す。APIは変えていない。
5. **作成後のタグ変更（実装済み・2026-10-03）。** `PUT /v1/instances/{id}/tags`（所有者か管理者。タグの集合を丸ごと差し替える）。`Name` も変更できる: 一覧・Proxmox のVM名・NetBox の台帳は変わるが、**VMの中のホスト名は変わらない**。CLI は `shakecloud instance tag`、Terraform Provider は `tags` の変更でインスタンスを作り直さなくなった、ポータルは一覧の「名前・タグを編集」。

1〜4 に API の変更は無い（openapi・client・cli・provider は触らない）。外部のライブラリやアイコン集は足さない。

## インスタンス画面の作り直し（実装済み・2026-10-03）

ほかのクラウドサービスと同じ考え方に揃えた。**API は変えていない**（`cloud/openapi/shakecloud.yaml` に手を入れず、既存のエンドポイントだけで組んだ）。

### 一覧（`#instances-view`）

- 列は**選択・名前・状態・IP・構成（vCPU / メモリ）・所有者**だけにした。ID・イメージ・ディスク・セキュリティグループ・タグ・状態の理由は一覧から外した。
- 一覧の上に**起動・停止・再起動・削除**の一括操作を置き、チェックしたインスタンスへまとめて実行する。**選択が無いとき、選んだ全台がその操作の対象になれるとき以外は押せない**（起動は停止中だけ、停止・再起動は稼働中だけ、削除は削除済み以外）。選択は 30 秒ごとの再読込と画面の絞り込みをまたいで保持する。
- 状態が合わない組み合わせのときに理由が分かるよう、ボタンの下に適用条件を書いている。
- 名前は詳細画面へのリンクにした。タグは一覧から外したが、**詳細のタグを押すと一覧へ戻ってそのタグで絞り込む**従来の導線を残した。
- 横スクロールを作らない方針（72rem 未満で行をカード表示、`labelCells` が `data-label` を付ける）はそのまま。`syncResourceRows` の列番号（インスタンスは `[2, 3, 4, 5]`）を新しい列に合わせて更新した。

### 詳細（`#instance-detail-view/<インスタンスID>`）

- 名前をクリックすると開く。`showView` を「`#` の最初の `/` までをビュー名として見る」形に広げ、ID をアドレスに持たせた。戻る・再読み込み・リンク共有が効く。
- 全項目（名前・ID・所有者・状態と理由・IP・MAC・イメージとゲストOS・構成・ディスクと種類・セキュリティグループ・タグ・作成/削除日時・SSH鍵）と、その1台への操作（電源・コンソール・名前とタグの編集・セキュリティグループの変更・削除・管理者だけのサイズ変更）を置いた。
- 名前とタグ・セキュリティグループ・サイズの編集フォームは、30 秒ごとに更新される読み取り部分の**外側**に置いた。ポーリングが入力中のフォームを消さない。別の画面へ移るときは未保存の入力を破棄してよいか確認する。
- コンソールはクリックの中で同期的に `window.open` する従来の順序を変えていない。
- 一覧の行にあった編集フォーム（`tr.edit-row` と `mountEditor` の行差し込み）は詳細へ移したので削除した。

### ボリュームへの適用（検討の結論: 今回は見送り）

同じ「選んでから実行」の型はボリュームにも合うが、今回は触っていない。アタッチ・デタッチ・拡張は「どのインスタンスへ」という行ごとの文脈が強く、一括にできるのは削除くらいで、得るものに対して変更範囲が大きい。一覧は既に ID・名前・所有者・大きさ・状態・接続先・パスで、横スクロールの方針も満たしている。次に触るときは、削除だけを一括操作にし、詳細を別ビューにするかを併せて決める。

### インスタンス画面の確認（2026-10-03）

実 API は使わず、同じ CSP（`default-src 'none'; script-src 'self'; style-src 'self'; connect-src 'self'; img-src 'self'; form-action 'self'; base-uri 'none'; frame-ancestors 'none'`）を返すローカルのモック API と実ブラウザー（Playwright の Chromium）で確認した。確認したのは、一覧の列と表示項目（ID・イメージ・ディスク・タグを出さない）、選択と一括操作の有効／無効（選択なし・状態混在・状態一致）、停止中インスタンスの起動、名前クリックでの詳細表示、名前とタグ・セキュリティグループ・サイズの各編集の保存、未保存のまま移動したときの確認、コンソールの同期 `window.open`、まとめて削除、390px で横スクロールが出ないこととカード表示、暗い配色。ブラウザーのコンソールエラーは0件。

機械的な確認は `node --check`（portal.js・portal-ui.js）、`go vet ./...`・`go test ./...`（cloud/api）、`tests/test_portal_assets.py`。

**未確認:** cloud-01 への配備（`cloud.yml`）と、実機の実データでの表示・操作。配備は [引き継ぎ台帳](../operations/handover.md)の残作業。
