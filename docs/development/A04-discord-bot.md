## 実装手順

1. 対象サーバー/チャンネルの許可リストと管理者、使用するコマンドを設定で定義し、A03との要求/応答を固定する。無関係なチャンネル本文は収集しない。
2. 模擬イベントとRAG模擬応答で実装し、要求者・返信先を認可情報として渡す。引用元・エラーを返す際も許可対象の情報だけに限定する。
3. 重複イベント、同時要求、タイムアウト、再接続を扱い、推論停止中は処理不能を短く返す。必要最小のDiscord権限と対象版のイベント要件を導入時に確認する。
4. 管理者が用意したテストBotとサーバーで接続検証し、Secretを配備先だけへ渡す。プロセス再起動の自動復帰、トークン更新、設定復元を手順化する。

## 依存と並列作業

- 開発開始: なし。Discord実アカウントやGPUなしでモック開発できる。
- 配備・切替: テストBot資格情報と招待権限、[I01](I01-resources.md)。実回答の結合は[A03](A03-rag.md)、推論は[A02](A02-ollama.md)。
- 競合調整: A03とAPI・認可契約を共有し、同じBotトークンを旧新プロセスで同時に使わない。game1停止時はBotも停止する。

## 検証・完了条件

- 許可チャンネルで応答し、未許可のチャンネル/利用者へ機密結果を送信しない。実接続試験はテストサーバー内で行う。
- RAG停止・タイムアウト・再配信でも無限再試行や重複応答を起こさず、Secretをログに出さない。
- 再配備・VM再起動後に再接続でき、設定復元・トークン交換を確認する。会話履歴を保存する場合は保持期限と削除方法を併記する。
