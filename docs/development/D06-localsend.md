更新日: 2026-09-12。種別: **資料のみ更新**。状態: **未着手（資料のみ。設計記載あり、端末の導入状況は未確認）**。

## 目的・現状の根拠

常設VM不要の端末間転送として、利用者が接続範囲と代替手段を判断できる案内にする。

[ネットワーク設計](../architecture/network-auth.md)と[運用設計](../architecture/operations.md)に同一LANでの端末間転送、VLAN／VPN越しの自動検出を前提にしない方針がある。

## 変更範囲

`docs/services/usage.md` にLocalSendの短い利用節を追加し、送受信端末で受信先を指定して確認する流れ、端末FWを確認する場所、同一LANで見つからない場合の切り分けを記載する。LANをまたぐ転送はNextcloudの案内へ誘導する。端末アプリの導入、FW変更、専用VM追加を実施済みとしない。

配備先: 文書は本リポジトリの `docs/`。公開サイトへの反映は文書検証後の既存運用に従い、この計画整備では公開しない。

## 検証・完了条件

同一LANの検出条件と遠隔転送の入口が区別でき、常設サーバー不要と明記される。文書・リンク・公開対象検証の通過で完了。端末2台の送受信結果を取得した場合だけ別途日付付きで追記する。

共通の確認は `python3 -m mkdocs build --strict`、内部リンクの実在確認、`python3 tools/check-publication.py`。実施していない実機確認を完了根拠へ追加しない。
