# A03 汎用RAGの構築

> **更新日** 2026-09-12 ・ **区分** 開発計画 ・ **読む人** 開発者

これは開発計画であり配備完了の記録ではありません。[配置・所有境界・並列作業の共通ルール](index.md)を参照してください。番号は実施順を表しません。

## 目的・現状

**状態**: 新規実装

[配置案](../architecture/operations.md)にOpen WebUI + pgvectorと文書権限分離の方針がある。本リポジトリに汎用RAGの配備・取り込み実装はない。Nextcloudの権限が自動継承される前提を置かない。

配備先・開発範囲: **game1。開発先 `stacks/rag-bot/`。ポケモン用途と別のDB・資格情報・保存先を持つ汎用文書検索と応答**。

## 実装手順

1. 最初の文書集合を明示的に共有が許されたテスト文書に限定し、文書ID・出典・閲覧対象と検索の認可入力を定義する。取り込み、検索、削除が同じ文書IDと権限を使う構成にする。
2. Open WebUI + pgvectorの専用構成と取り込み処理を作る。Embeddingモデル・次元を記録して固定し、ポケモンDB/図鑑文書と共有しない。Nextcloudは明示指定した共有範囲だけ取得する。
3. Botからは利用者・対象チャンネルを含む要求を受け、許可された文書に絞って検索してから推論する。応答には参照元を添え、根拠がない場合はその旨を返す。文書内の指示で権限やツール実行を変更しない。
4. 文書更新・削除・アクセス権変更を検索対象へ反映する。認証した管理者だけが取り込みを操作し、DB・設定・文書/索引の復元手順を作る。

## 依存と並列作業

- 開発開始: なし。ローカルテスト文書と推論の模擬応答でAPI・権限テストを開始する。
- 配備・切替: [I01](I01-resources.md)、実推論確認は[A02](A02-ollama.md)。Nextcloud実データの接続は[W03](W03-nextcloud.md)と権限確認後。Botの完成はRAG単体開発の前提にしない。
- 競合調整: A04と要求/応答・認可情報のインターフェースを先に合意する。game1のGPUと重い取り込みはA02/G03と調整する。

## 検証・完了条件

- 一般/限定文書の検索、他利用者・未許可チャンネルの拒否、文書の削除・権限撤回後に検索結果へ出ないことを確認する。
- 推論停止、空結果、取り込み失敗で権限を緩めず、機密本文やSecretをログへ残さない。
- DB・文書・設定を隔離復元して同じ出典を検索できる。再配備・VM停止再開後に状態を保つ。
