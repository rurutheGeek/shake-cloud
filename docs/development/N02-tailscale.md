# N02 Tailscaleの復旧経路・DNS

更新日: 2026-09-12。区分: **運用改善・実機確認**。状態: 計画作成済み、復旧経路の合格未確認。

## 目的・現状・配備先

K11とservices-01の停止中も、既存ラズパイのTailscaleから管理LANへ戻れるようにする。[VPN設計](../architecture/vpn.md)が独立経路を要求し、[クラウド運用](../operations/cloud.md)にはTailscale DNSのSERVFAILとサブネットルート未設定の過去記録がある。過去記録を現状の障害断定に使わず、現在の端末・設定を読み取り確認する。

## 変更範囲と実装

1. ラズパイ、管理端末、DNS解決先、広告・承認済みルート、ACL、端末キー期限を確認する。秘密値や個人の端末台帳は公開文書へ出さない。
2. 管理に必要なサブネットのみ広告・承認し、復旧管理者に絞る。既存DNSと併用し、K11停止時にも管理ホストを特定できる接続先を管理者用に保管する。
3. Tailscaleの本人確認と復旧情報をK11内identityから独立させる。新規利用者を自動的に復旧管理グループへ入れない。
4. セルフホストVPNとの切替手順、重複経路・DNSキャッシュの確認、設定の退避・戻し方を運用資料へ記す。両VPNの同時default routeを前提にしない。

## 依存と並列作業

- **開発開始:** 他IDの完了待ちは不要。資料、ACL・DNSの期待値、接続試験表を作れる。
- **実機設定:** 既存ラズパイとtailnetの管理権限、宅外試験端末が必要。[N01](N01-vpn.md)の配備完了は不要。
- **競合:** ルータ・DNS・tailnetの共有設定は[N01](N01-vpn.md)・[N03](N03-vlan.md)・[I04](I04-cloud-dns.md)と調整する。K11停止試験は全VM利用者と[O03](O03-restore.md)へ通知して時間を確保する。

## 検証・完了条件

- 宅外端末から、通常状態・services-01停止・identity停止・K11停止の各条件で、管理用DNSと到達範囲を確認する。K11全停止ではProxmoxへ接続できるとは判定せず、ラズパイ到達と管理LAN経路の存続を確認し、再起動後にProxmoxへ再接続する。
- 許可外利用者の管理アクセスを拒否し、復旧端末キー更新後も接続できる。
- VPN切替後のDNS不調を再現・解消でき、元の設定へ戻せる。結果と実施日を記録する。
