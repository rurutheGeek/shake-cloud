# W07 RomMの新規導入

> **更新日** 2026-09-13 ・ **区分** 開発計画 ・ **読む人** 開発者

これは開発計画であり、配備完了の記録ではありません。[配置・所有境界・並列作業の共通ルール](index.md)を参照してください。番号は実施順を表しません。

## 目的・現状

**状態**: 独立Compose・状態管理を実装。game1実機確認と認証統合は未実施

[配置案](../architecture/operations.md)と[ゲーム設計](../architecture/gaming.md)に希望がある。**RomMはゲームVMのライブラリ管理であり、メディア（音楽・本）の移行ではない。**`stacks/romm/` に独立Compose・状態管理を実装済みだがgame1へは未配備で、ゲーム起動・通信プレイ連携まで実装済みとは扱わない。

配備先: **game1**。開発先は `stacks/romm/`。RomM＋MariaDBの独立Compose、ROM原本の読み取り専用マウント、秘密値生成、ダイジェスト固定、冷間バックアップを実装した。ライブラリ管理を最初の完了単位とし、Wolf/Azahar連携の結果は分けて記録する。

## 実装手順

1. 導入時の公式構成で対応版・固有DB・追加サービス・必要Secret・永続化箇所を確認し、採用版を固定する。既存Nextcloud DBとの強制共有やPostgreSQLへの強制統一をしない。
2. 所有する原本の配置、管理対象、メタデータ更新権限を決め、原本とアプリDBを分離したComposeを作る。利用者・管理者の認証とidentity連携方式を対象版で確認し、採用方式を本書へ記録する。
3. 少数のライブラリで取込・検索・閲覧を検証し、容量と走査時間を測って移す。ROM原本・アプリDB・メタデータはgame1の中でもゲーム本体・AIと分け、セーブやプロフィールを共有原本へ混ぜない。ゲーム中の大量走査を避ける。

## 依存と並列作業

- 開発開始: なし。製品調査・少数原本のテスト構成を並列作成できる。
- 配備・切替: [I01](I01-resources.md)の容量確認、既存game1への配備権限・保存先の確認、[G03](G03-game-ai-resources.md)の負荷調整、[N05](N05-https.md)の入口。エミュレータ結合検証だけ[G02](G02-azahar.md)の準備後。
- 競合調整: G01〜G03とゲーム・AI・ディスク・走査負荷を調整する。G02とはROM原本の受渡しだけを共有し、セーブと利用者設定の所有者を分ける。media-01のW03〜W06とは原本・容量を共有しない。

## 検証・完了条件

- 取込・検索・再走査でライブラリが保たれ、一般利用者が管理設定や他人の状態を変更できない。
- 採用した認証統合が動き、未認証アクセスが拒否される。外部メタデータ取得失敗時も原本を失わない。
- DB・設定・原本の復元とVM再起動後の再開を確認する。ゲーム起動連携の可否はライブラリ管理の合格と混同しない。
