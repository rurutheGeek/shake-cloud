# G02 Azahar二人利用・非公開ルーム

更新日: 2026-09-12。これは開発計画であり配備完了の記録ではありません。[配置・所有境界・並列作業の共通ルール](index.md)を参照してください。番号は実施順を表しません。

## 目的・現状

状態: **新規構成管理・実機確認**。

[ゲーム設計](../architecture/gaming.md)にAzahar二つ、非公開ルーム、利用者別セーブの方針がある。現行コードに配備定義はなく、作品別の交換・対戦は未検証。

配備先・開発範囲: **game1。開発先 `stacks/game/`。利用者ごとのセーブ・設定・入力と、VM内の非公開ルーム**。

## 実装手順

1. 導入版のLinux実行方式・ルーム起動方法を一次資料で確認し固定する。既存手動環境があればセーブ・ユーザーデータを先に保全する。
2. 二人のAzaharに別の永続ディレクトリとプロフィールを割り当てる。原本は必要な範囲で読み取り専用共有し、セーブ・キャッシュを共有しない。
3. 外部公開しないルームを用意し、同じ作品/更新データ/エミュレータ版で二人の接続を確認する。Wolfへ独立アプリとして登録し、ロビーの同一画面共有と区別する。
4. 30〜60分の移動・戦闘・交換/対戦を含む試験を行い、セーブ保全、切断復帰、ルーム再起動、復元操作をまとめる。

## 依存と並列作業

- 開発開始: なし。設定・ディレクトリ設計・ルーム単体準備をG01と並列に進める。
- 配備・切替: 手元の利用可能なゲームデータ、[G01](G01-wolf.md)の配信基盤、[I01](I01-resources.md)。[W07](W07-romm.md)が未完でも直接原本を用意して検証できる。
- 競合調整: G01とアプリ登録設定を調整する。同じセーブを二つのプロセスが開かない。長時間GPU試験はA02/G03と調整する。

## 検証・完了条件

- 二人が別画面・音声・入力・セーブで利用でき、交換/対戦が対象作品で成立する。非公開ルームが許可外から利用できない。
- 速度・音切れ・フレーム時間と初回シェーダー生成を記録し、再接続後も進捗を維持できる。
- ゲーム終了時の整合セーブを別保存先から復元でき、再配備・VM再起動後も設定とセーブが残る。
