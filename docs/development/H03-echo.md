# H03 Echo・Alexa連携

> **更新日** 2026-09-12 ・ **区分** 開発計画 ・ **読む人** 開発者

これは開発計画であり配備完了の記録ではありません。[配置・所有境界・並列作業の共通ルール](index.md)を参照してください。番号は実施順を表しません。

## 目的・現状

**状態**: 今回は見送り（2026-09-12決定）。方式の比較材料は残す

[家電の構成案](../architecture/operations.md#home-devices)はEcho Gen2を既存端末とし、Alexaからの家電操作とEchoへの音声通知を別機能としている。利用者と協議し、**Home Assistant Cloudの契約も独自Skillの公開入口もいまは作らず、H01とH02を先に完成させる**方針にした。HAの8123はルーターへ公開していない（127.0.0.1と既存Caddyのみ）。

配備先・開発範囲: **既存Echoとservices-01のHome Assistant Container。開発先 `stacks/home-assistant/` のAlexa用手順**。

## 実装手順

1. Echo型番/アカウントと操作したい家電、通知要否を整理する。Echoを汎用Bluetooth proxyやThread機器として扱わない。
2. 導入時の公式情報でHome Assistant Cloudと独自Skill方式のアカウント・料金・外部到達条件を比較し、採用方式と公開する機器を本書へ記録する。新しい契約が必要ならその決定を実配備の前提として残す。
3. 選定した認証/接続で一つのテスト機器だけ公開して操作を確認する。音声通知は個別に対応可否と認証要件を調査し、操作側の完了を通知対応待ちにしない。

## 依存と並列作業

- 開発開始: 方式比較・機器一覧はH01と並列。アカウント依存の実接続は既存契約/選択の確認後。
- 配備・切替: [H01](H01-home-assistant.md)と操作対象。接続方式が外部入口を要する場合だけ[N04](N04-public-edge.md)に接続要件を渡す。VPNのみでAmazonから到達できるとしない。
- 競合調整: H01の公開設定とH02の対象機器名を調整する。方式決定前にHAの8123をルーターへ公開しない。

## 検証・完了条件

- 許可した機器だけ音声操作でき、アカウント連携解除後は操作できない。
- HA再起動/一時切断後の復帰と再リンク手順を確認する。通知の成否は操作機能と分けて記録する。
- HA設定復元後に再連携でき、トークンや個人アカウント情報を公開資料へ含めない。未採用/条件待ちの場合は不足条件を残す。
