よく使う操作の手順です。管理者向けの詳しい手順は運用ドキュメントにもあります。

Windows 11 をISOからインストールする

  1. 「ISO」に Win11 のISO（OS=Windows 11） と virtio-win のISO があるのを確認します（共有ISOにあればそのまま使えます）。
  2. 「インスタンスを作成」→ 作成方法「ISOからインストール」。インストールISO=Win11、ゲストOS=Windows 11、ドライバISO=virtio-win、ルートディスクは64 GiB以上、メモリは4096 MiB以上にします。
  3. 起動したら一覧の「コンソール」を開きます。インストール先の一覧が空のときは「ドライバーの読み込み」→ virtio-win のCDの viostor\w11\amd64 を開き、「Red Hat VirtIO SCSI controller」を選びます（このポータルが作るディスクは virtio0 のため。vioscsi は scsi0 用で見つかりません）。
  4. ネットワークも使うなら、同じ手順で NetKVM\w11\amd64 を読み込みます。NICが「Red Hat VirtIO Ethernet Adapter」と認識されれば成功です。
  5. 一覧の「IP」列にある割り当てIPをWindows側に設定します（ゲートウェイとDNSは 192.168.10.1）。セットアップ中なら Shift+F10 → 次のコマンド例（IPは例）:
    netsh interface ip set address "Ethernet" static 192.168.10.100 255.255.255.0 192.168.10.1
    netsh interface ip set dns "Ethernet" static 192.168.10.1
  6. 「インターネットに接続していません」で先に進めないときは、Shift+F10 → oobe\bypassnro → Enter。自動で再起動し、ローカルアカウントを作れます（BypassNRO.cmd と同じ）。
  7. IPやホスト名を自動でしたい場合は、「ISO」の cloudbase-init をCDで開いてMSIを実行し、再起動します。

リモートデスクトップ（RDP）で入る（Windows 11 Pro）

RDPのホスト側は Windows 11 Pro だけです（Home不可）。

  1. Windowsで「設定」→「システム」→「リモートデスクトップ」をオン（または sysdm.cpl → リモート）。PowerShellなら:
    Set-ItemProperty -Path 'HKLM:\System\CurrentControlSet\Control\Terminal Server' -Name fDenyTSConnections -Value 0
    Enable-NetFirewallRule -DisplayGroup "リモート デスクトップ"
  2. 接続するアカウントにパスワードを設定します（パスワード無しは拒否されます）。
  3. ポータルで、このVMのセキュリティグループに TCP 3389・送信元 192.168.10.0/24 の受信ルールを追加します（既定グループは全許可なので、絞っていなければ不要）。
  4. 手元のPCから mstsc /v:192.168.10.100（一覧の割り当てIP）で接続します。

OEMのWindows 11ライセンスをこのPVEへ持ち込む（管理者）

GMKtec K11 のように、このPVEホストへOEMのWindowsがプリインストールされていた場合、そのライセンスをVMへ引き継げます（同一の物理機内のみ。1ライセンス1台）。ホストのrootが要るため、ポータルからは実行できません。

  1. ポータルでWindows VMを作成し、VMIDを確認します（Proxmoxで qm list | grep i-）。
  2. ホスト（root）でOEM情報をVMへ渡します:
    mkdir -p /etc/pve/qemu-server/<vmid>
    cat /sys/firmware/acpi/tables/MSDM > /etc/pve/qemu-server/<vmid>/slic_table
    qm set <vmid> --args "-acpitable file=/etc/pve/qemu-server/<vmid>/slic_table"
  3. dmidecode -s system-manufacturer / system-product-name / system-uuid / system-serial-number の値でSMBIOSを合わせます。PVE 9はスペース入りを拒否するため、値はbase64にして base64=1 を付けます（例: GMKtec / NucBox K11 / Default string）:
    qm set <vmid> --smbios1 'uuid=<UUID>,manufacturer=R01LdGVj,product=TnVjQm94IEsxMQ==,serial=RGVmYXVsdCBzdHJpbmc=,base64=1'
  4. VMを停止→起動（args/smbios1 は起動時に反映。リセットでは反映されません）。Windowsをインストールするとプロダクトキーを聞かれずOEM認証が効きます。インストール済みなら slmgr /ato。

VMを削除したら /etc/pve/qemu-server/<vmid>/ を掃除してください。

電源操作ができない／再起動が終わらない

作成・起動・停止・再起動・削除のいずれかが処理中の間は、一覧の状態に「〜処理中…」と表示され、別の電源操作は受け付けません。処理中にボタンを押すと理由を案内します。完了まで待ってください。ACPIに応答しないゲスト（Windowsでguest agent未導入など）では、再起動は自動で強制リセットに切り替わります。

コンソールが開かない

ブラウザがポップアップをブロックした場合、画面に表示される「〜のコンソールを開く」リンクを押してください（5分で無効）。もう一度「コンソール」を押して発行し直すこともできます。コンソールへの貼り付けはWindows側が対応しておらず使えないことがあるので、短いコマンドを入力してください。

IPアドレス・削除の注意

一覧の「IP」列が割り当てられた固定IPです。Linuxのイメージは起動時に自動設定されます。WindowsやISOから入れたゲストは自分で設定してください。VMを削除するとルートディスクも消え、接続済みの追加ボリュームは切り離されて残ります。
