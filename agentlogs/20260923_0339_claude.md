# 追補2: テスト規約への導線（同日）

## 指摘

テストを整頓した（`3fa5cc1` で `tests/support.py` と `tests/README.md` を追加）が、テスト設計はどのページに載っているのか。

## 調べた結果

**ハンドブック（`docs/`）には無い。** 正本は `tests/README.md`（63行）で、中身は充実している。

- 1対象1ファイルと命名規則（`test_<stack>_stack.py` ほか）
- テストクラスを層で分ける、各テストは不変条件を1つ、docstringに「何が壊れると困るか」
- `tests/support.py` のヘルパ6種と、3ファイル以上で重複したら移すルール
- `tests/__init__.py` を置かない理由、`/tmp` に残さない書き方
- `ansible-playbook` 不在時のskipとCIでの扱い

問題は場所ではなく**導線**だった。

| 確認 | 結果 |
| --- | --- |
| `mkdocs.yml` の nav | 無い |
| `docs/` から `tests/README.md` への参照 | 0件 |
| ドキュメント地図 | 載っていない |

`docs/` 側にあるのは実行コマンド（`contributing-docs.md` §8・`operations/verify.md`）と、個別テストへの言及約20箇所だけ。テストを書き足そうとしてハンドブックを読んだ人は、命名規則も `support.py` の存在も知らないまま書くことになる。

さらに `tests/README.md` には「**ドキュメントへテスト件数を書かない**」という `docs/` を直接縛る規約があるのに、ハンドブック側がそれを知らなかった。

## 直した内容

`docs/` にテスト設計ページを新設する案は採らなかった。**同じ規約が2箇所になって必ず食い違う**ため。正本は `tests/README.md` のままにして、導線だけを足した。

1. `contributing-docs.md` §8: テスト規約の正本が `tests/README.md` であることと、「件数を書かない」規約がこのページを縛ることを明記
2. `operations/verify.md`: 手元で流す検査の節から同じ導線
3. `development/I05-service-state.md`: 唯一残っていたテスト件数の記載（「`tests/test_tf_services.py` の22件」）をファイル参照へ

リンクではなくbacktickでパスを示す形にした。リポジトリ内ファイルの参照はこれがこのハンドブックの慣例で、`docs/` の外へ相対リンクを張ると `mkdocs build --strict` が落ちるため。

`router-troubleshooting.md` の「今回の 2 件は反映済み」はトラブル事象の件数でテスト件数ではないので残した。
