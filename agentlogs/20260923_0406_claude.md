# 旧環境の残骸を整理する（2026-09-23）

## 依頼

前回の監査で報告した「どこからも参照されていない `stacks/hub`・`stacks/sso`・`hub.yml`・`sso.yml`」を整理する。

## 削除前の確認

消すのは戻しにくいので、生きている依存を先に全部洗った。

### リポジトリ自身が旧環境だと宣言していた

`stacks/identity/compose.yaml` の2行目にこう書かれていた。

> 作業機上の stacks/hub は検証用で、ここへは移行しない（2026-09-10 に新規構築）

つまり `stacks/hub` は services-01／media-01 へ分割する前の検証用スタックで、`stacks/identity/` が後継。判断の裏付けになった。

### `stacks/sso`

`.gitignore` の2行以外、**参照ゼロ**。完全に孤立していた。

### `stacks/hub`

スタックとしては孤立していたが、生きた依存が4つあった。**これを先に処理しないとCIが壊れる。**

| 依存 | 扱い |
| --- | --- |
| `.github/workflows/validate.yml` が `stacks/hub/requirements.txt`（mkdocs・requests・PyYAML）を入れていた | `tools/requirements.txt` へ集約。requests は既にあったので mkdocs と PyYAML を追加し、CIは `-r tools/requirements.txt` の1本に |
| `tests/test_identity_attributes.py` が `stacks/hub/identity_attributes.py` を import | 下記 |
| `tools/check-publication.py` が `stacks/hub/.env`・`oidc-secrets.json` を秘密値の走査対象にしていた | 該当パスを外した |
| `.gitignore` 4行・`.yamllint` 1行 | 外した |

### テストを消してよいか

`identity_attributes.attributes_for` は「メールアドレスが変わっていない間だけ verified を保つ」ロジック。**同等の関数が `stacks/identity/configure.py` に存在しない**ことを確認した。現行の identity は users.json の同期ではなく招待（`invitations.py`）で利用者を作るため、この関数の出番自体が無い。

呼び出し元を全文検索したところ、`hub.yml`・`sso.yml`・このテストの3つだけだった。**テストが守っている振る舞いが現行のどこにも無い**ので、対象ごと削除した（緑にするためにテストを消したのではなく、対象が消えたため）。

### docs-site が巻き込まれないか

`stacks/hub/` に `media-stack-docs-build.service.j2`・`.timer` があったので確認した。現行の `platform/ansible/roles/docs_site/` は `stacks/docs/` を使っており、`stacks/hub` には触れていない。ドキュメントサイトの配備は無関係。

### 文書側

`docs/`・README・CONFIGURATION のいずれも `stacks/hub`・`stacks/sso` に言及していなかったので、文書の修正は不要だった。

## 実施した順番

CIを壊さないよう、**依存の移動を先に**行った。

1. `tools/requirements.txt` へ mkdocs・PyYAML を追加（コメント付き）
2. `validate.yml` を `-r tools/requirements.txt` の1本に
3. `check-publication.py`・`.gitignore`・`.yamllint` から死んだパスを削除
4. `stacks/identity/compose.yaml` の注釈から、消えるディレクトリへの言及を外した
5. `stacks/hub/`・`stacks/sso/`・`hub.yml`・`sso.yml`・`test_identity_attributes.py` を削除
6. 残存参照ゼロを全文検索で確認

## ついでに直したこと

依存が `tools/requirements.txt` に集約できたので、README の検証節が「mkdocs・yamllint などを入れた `.venv` を使います」と曖昧だったのを、実際のコマンドに置き換えた。新しく入った人が `.venv` に何を入れるか調べなくて済む。
