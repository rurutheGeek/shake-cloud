# 内容の不足の監査と、リポジトリからの補完（2026-09-23）

## 依頼

現状との食い違い（前回）だけでなく、**内容そのものの不足**を監査し、リポジトリの内容から埋める。

## 監査のやり方

前回の「書いてあることが正しいか」ではなく「**必要なものが書かれていないか**」を見た。impressionで探すと漏れるので、コード側の在庫と文書を突き合わせた。

1. `platform/ansible/*.yml`（Playbook）が文書に出てくるか
2. `platform/terraform/dns.yaml` の全レコード（＝利用者が開けるもの）に案内があるか
3. `stacks/*` が運用／利用者ページを持つか、開発計画しか無いか

## 検出方法の誤りと訂正

最初にPlaybookをファイル名で grep したところ10本が「未言及」と出たが、**`bootstrap.md` は `site.yml --tags pve-users` の形で呼んでいた**。タグ経由も数えて再検査し、`pve-users.yml` は誤検出と判明。残りは下記。

## 見つけた不足

### 1. 監視に運用ページが無い（最大の欠落）

`monitor-01` は稼働中で、アラート23件・dead man's switch・UPS自動停止まで実装されているのに、**運用ページが存在しなかった。** 実質的な記述は `development/M01-monitoring.md` だけで、これは開発計画であり、節の並びも「2026-09-21追加」「2026-09-22追加」と**変更履歴の形**をしている。アラートが鳴った人が読む形になっていない。

他の配備済みサブシステム（AdGuard・ルータ・バックアップ・バルクストレージ・Garage・Kubernetes・NetBox・identity・クラウド・Vaultwarden・Nextcloud）はすべて運用ページを持つ。監視だけが例外だった。

`docs/operations/monitoring.md` を新設し、リポジトリの実体から書いた。

| 節 | 出典 |
| --- | --- |
| 何が動いているか（6コンテナ・ポート・保持15日・6ジョブ・5ダッシュボード） | `stacks/monitoring/compose.yaml`・`prometheus.yml`・`grafana/provisioning/` |
| 入る（OIDCの役割対応・identity停止時のローカル復旧） | 配備台帳 §4 |
| **アラートが鳴ったら**（23件を6グループで表にし、意味と最初に見る場所） | `stacks/monitoring/prometheus/alerts.yml` |
| 鳴らないことの検知（dead man's switch） | M01 から運用部分だけを移し、経緯はM01に残した |
| 直す・入れ替える（`manage.py` の7アクション・再配備・ホスト側exporter） | `stacks/monitoring/manage.py`・`platform/ansible/monitoring.yml`・`pve-node-exporter.yml`・`pve-nut.yml` |
| 限界 | 監視と監視対象が同一ホスト、media-01・game1にnode_exporter無し、保持15日 |

`severity: critical` は `SmartDeviceUnhealthy` の1件だけという事実も明記した。

### 2. Grafana に利用者向けの案内が無い

`dns.yaml` の全レコードを利用者向けページと突き合わせたところ、Grafana だけ「**一般利用者も `users` で Viewer として入れる**」のに案内が無かった（他の未案内は adguard・router・pve・functions で、いずれも管理者向けなので正しい）。`services/index.md` に「様子を見る」節を足した。

### 3. media-01 の単体配り直しが書かれていない

文書にあるのは傘の `media.yml` だけで、`media-kavita.yml`・`media-navidrome.yml`・`media-freshrss.yml` などの個別Playbookが無かった。1つだけ直したい運用者は Playbook ディレクトリを読むしかない。

さらに重要な落とし穴として、**`media-*.yml` 本体だけではOIDCが無効のまま起動する**（秘密値を配るのは `media-*-sso.yml` 側）。これはPlaybook冒頭のコメントにしか書かれておらず、忘れると「ログイン画面が出ないまま中身が見える」。`operations/services.md` に実行順の表と、このSSO分離の注意を足した。

## 見つけたが直していないもの（判断が要る）

**`platform/ansible/hub.yml` と `sso.yml`、`stacks/hub/`・`stacks/sso/` は、どこからも参照されていない。** `site.yml` にも入っておらず、他のPlaybook・スクリプト・文書のいずれからも呼ばれない。`hosts: media` で「hub と共有認証を配る」内容から、services-01／media-01 に分割する前の旧環境の残骸とみられる。

ただし `stacks/hub/requirements.txt` は CI が使っているので、ディレクトリ全体が死んでいるわけではない。**文書の不足ではなくコードの整理なので、消すかどうかは利用者の判断**として報告するに留めた。
